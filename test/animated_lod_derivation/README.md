# Manual animated LOD derivation

This C3 0.8.3 target derives two deterministic face-subset levels for each of the two Quaternius mannequin primitives. It uses the public glTF AssetStore loader, verifies the immutable input SHA256, compacts first-used source vertices, and preserves each retained attribute and the complete skin identity.

The [fixture README](../fixtures/animated_lod/README.md) defines the derivation, provenance, binary layout, counts, hashes and quality limitation.

Build from the repository root:

    c3c build animated_lod_derivation --path test/animated_lod_derivation

Generate into an existing output directory:

    test/animated_lod_derivation/build/animated_lod_derivation.exe SOURCE.glb OUTPUT_DIR [EXPECTED_DIR]

SOURCE.glb must be the original examples/assets/quaternius/AnimationLibrary_Godot.glb at SHA256 272d5c1e2c27f566595ece27b6985935d42dcee1dacee1b320af9f0c40d5c97c. The tool disables animation/light/camera import and explicitly sets generate_tangents=false. Authored streams remain available; synthesized tangents are excluded. File names and source primitive order are fixed.

EXPECTED_DIR enables exact regeneration comparison of all four files. Successful generation/comparison exits 0, input/data/I/O/comparison failure exits 1, bad arguments exit 2. Wrong hashes are rejected before model publication or fixture writes. The tool additionally checks source stream extents, both skins' complete joint/bind identity, selected-corner coherence, strict reductions and decoded output attribute/bind bits before saving. SHA256SUMS is generated by C3.

This manual target is outside scripts/build.py --test. Its build outputs are isolated under this directory. It creates no GPU device and contains no shader, native binding, download or Python mesh-processing path. A future test-side regeneration/equality case can use the same recipe and documented arrays; no production API is introduced by the fixture format.
