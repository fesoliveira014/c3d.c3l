# Shader packages

An add-on or an application that ships GLSL compiles it offline with `scripts/build_shaders.py` into a committed C3 file
of `$embed` constants. A shader package is a directory with `shaders/shaders.json`. The generated file declares the
SPIR-V as constants a module reads when it builds a `ShaderDesc` ([Custom shaders](custom_shaders.md)), and a table of
the package's GLSL includes for the in-process compiler.

## Quick start

A package has a manifest, its GLSL sources, optional includes and a generated output:

```
addons/c3d_landscape.c3l/
├── shaders/
│   ├── shaders.json
│   ├── terrain.frag.glsl                         entries' sources
│   ├── include/landscape/terrain_height.glsl     includes, under the package name
│   └── spv/                                      build output, not committed
└── src/shaders.c3                                the generated output, committed
```

The manifest lists every compiled stage and the defines it uses (an excerpt of the landscape package):

```json
{
  "module": "c3d::landscape",
  "output": "src/shaders.c3",
  "flags": ["DEPTH_ONLY", "INSTANCED", "VELOCITY", "RT_SHADOWS", "SCENE_TRACE_BVH"],
  "entries": [
    { "shader": "terrain_fragment", "source": "terrain.frag.glsl", "stage": "frag", "defines": [] },
    { "shader": "terrain_fragment", "source": "terrain.frag.glsl", "stage": "frag", "defines": ["RT_SHADOWS"] },
    { "shader": "terrain_fragment", "source": "terrain.frag.glsl", "stage": "frag", "defines": ["RT_SHADOWS", "SCENE_TRACE_BVH"] },
    { "shader": "terrain_vertex", "source": "terrain.vert.glsl", "stage": "vert", "defines": [] },
    { "shader": "terrain_vertex", "source": "terrain.vert.glsl", "stage": "vert", "defines": ["DEPTH_ONLY"] }
  ]
}
```

Compile and write the output:

```bash
python3 scripts/build.py --regen                                    # in this repository
python3 lib/c3d.c3l/scripts/build_shaders.py --package path/to/package   # in an application
```

The module reads the generated constants and registers the shader:

```c3
module c3d::landscape::terrain;

import c3d::landscape @public;

ShaderDesc desc = {
    .fragment         = landscape::TERRAIN_FRAGMENT_SPIRV[..],
    .traced_fragment  = {
        .hardware = landscape::TERRAIN_FRAGMENT_RT_SHADOWS_SPIRV[..],
        .software = landscape::TERRAIN_FRAGMENT_RT_SHADOWS_SCENE_TRACE_BVH_SPIRV[..],
    },
    .vertex           = {
        .shaded = landscape::TERRAIN_VERTEX_SPIRV[..],
        .depth  = landscape::TERRAIN_VERTEX_DEPTH_ONLY_SPIRV[..],
    },
    .param_block_size = TerrainParams::size,
};
ShaderId shader = assets.add_shader(&desc, "terrain")!;
```

## Manifest

| Field | Required | Meaning |
| --- | --- | --- |
| `module` | Yes | Module of the generated file. Its last component `<name>` names the include directory and the include table |
| `output` | Yes | Generated C3 path relative to the package root; committed |
| `flags` | Yes, may be empty | Defines entries may use, in the order that names the constants. Vertex entries name `DEPTH_ONLY`, `INSTANCED` and `VELOCITY` here for their depth, instanced and [velocity](custom_shaders.md#velocity-form) forms |
| `entries[]` | Yes | `shader`, `source` (under `shaders/`), `stage` and optional `defines` (a subset of `flags`) |

`stage` is a glslang stage name: `vert`, `frag`, `comp`, `geom`, `tesc`, `tese`, `rgen`, `rmiss`, `rchit`, `rahit`,
`rint`, `rcall`, `task` or `mesh`. An entry is unique by `(shader, defines)`.

## Includes

A package compiles against core's include roots, so every [public include](custom_shaders_reference.md#public-includes)
is available, plus its own `shaders/include/`. Package includes live in `shaders/include/<name>/` and are written
`#include "<name>/x.glsl"`, also between the package's own includes, because the in-process resolver matches names
exactly.

- Another package's includes are never visible. Cross-package includes are unsupported.
- The build does not probe package includes. The entries that include them compile them.
- A package name cannot equal a first-level directory of core's include roots (`generated`, `internal`), and an include
  name cannot equal a core include or another package's include in the same run.

## Generated file

SPIR-V goes to `<package>/shaders/spv/<shader>{_<define>}.spv`, with the defines in `flags` order. The generated file
declares:

- the module;
- one `@private` constant per entry, named `<SHADER>{_<DEFINE>}_SPIRV`, with the defines in `flags` order;
- when the package has includes, the public `<NAME>_SHADER_INCLUDES` table for `compile_glsl(includes:)`, with
  `import c3d::asset;` as its only import. The file never imports a render-layer module.

```c3
// Generated by build_shaders.py from shaders/shaders.json - do not edit.
module c3d::landscape;

import c3d::asset;

const char[*] TERRAIN_FRAGMENT_SPIRV @private = $embed("../shaders/spv/terrain_fragment.spv");
const char[*] TERRAIN_FRAGMENT_RT_SHADOWS_SPIRV @private = $embed("../shaders/spv/terrain_fragment_rt_shadows.spv");
...
const char[*] INCLUDE_LANDSCAPE_TERRAIN_HEIGHT_TEXT @private = $embed("../shaders/include/landscape/terrain_height.glsl");

<*
 GLSL includes of this package, by the name a shader writes.
*>
const asset::ShaderInclude[7] LANDSCAPE_SHADER_INCLUDES = {
    { .name = "landscape/terrain_height.glsl", .text = (String)INCLUDE_LANDSCAPE_TERRAIN_HEIGHT_TEXT[..] },
    ...
};
```

The SPIR-V constants are `@private` to the package's module. A submodule of the add-on reads them with
`import c3d::landscape @public;`, which lifts the private visibility for the importing module. Every add-on with
submodules follows this rule. `add_shader` copies the bytes into the store. Payload structs stay hand-mirrored C3
structs with `$assert` size pins.

## Build

- **In this repository.** `scripts/build_shaders.py` discovers every `addons/*/shaders/shaders.json` and
  `test/shaders/shaders.json`. `python3 scripts/build.py` compiles them after core's registry and probes, and `--regen`
  rewrites their outputs. Without `--regen`, a stale output fails the shaders step ([Development](development.md)).
- **Outside the repository.** `python3 lib/c3d.c3l/scripts/build_shaders.py --package <dir>` compiles the named package
  (repeatable). `--check` verifies the output instead of writing it. With `--package` the script compiles only the named
  packages against core's include roots and writes only their outputs. It reads neither `shaders/variants.json` nor
  `lib/`, so it also runs from a copy that holds just `scripts/build_shaders.py` and `shaders/{common,generated,gpu}`,
  and from the release's shader tools ([Release](release.md#shader-packages)).
- **Tools.** The script needs Python 3.10 or newer and `glslangValidator` on `PATH`. It targets Vulkan 1.3 and SPIR-V
  1.5.
- **Version control.** Commit `shaders.json`, the sources, `shaders/include/**` and the output. `shaders/spv/` is build
  output and is ignored.
- **No package.** An add-on without `shaders/shaders.json` needs nothing.

### Manifest errors

A manifest error stops the step with `[shaders] manifest error:` and exits 1. The causes are:

- a missing field;
- an unknown stage or a missing source;
- a define outside `flags`, or duplicate flags;
- a duplicate `(shader, defines)`;
- a `.glsl` under `shaders/include/` outside `<name>/`;
- a package name that equals a first-level directory of core's include roots;
- an include name that equals a core include or another package's include in the same run;
- a `--package` directory without `shaders/shaders.json`.

A shader that glslang rejects stops the step with glslang's output.

## Limits

- Cross-package includes are unsupported.
- An entry can use only defines the manifest lists in `flags`.
- The generated constants are private to the package's module. Submodules need `import <module> @public;`.
